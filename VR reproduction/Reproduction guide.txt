Yantai VR prototype — setup and reproduction
Documentation updated 24 November 2026. Recorded software checks: 6 November 2026.

1. Prototype and files

Fan Huang implemented the Unity/C# prototype to adjust three linked gallery volumes and inspect the intervening spaces in VR. SteamVR/OpenVR supplies the tracking, input and navigation components. The original study used HTC Vive.

Yantai VR - Unity source.zip contains Assets, Packages and ProjectSettings, including SampleScene, FBX models, control scripts, bindings and the local OpenVR dependency. Yantai VR - Archived Windows build.zip contains the executable and runtime files. Source file manifest.csv records the source hashes. Editor caches are omitted; historical instructions and technical logs are retained separately.

2. Open the Unity project

a. Extract the source archive into a new folder with Assets, Packages and ProjectSettings at its root.
b. ProjectVersion.txt records Unity 2022.3.53f1c1. A separate copy was compiled and checked in 2022.3.62f3c1 on 6 November 2026. If using another version, work on a copy and record package changes.
c. Let Package Manager restore the dependencies. The OpenVR archive is included at the relative path in Packages/manifest.json.
d. Open Assets/Scenes/SampleScene.unity. On the Player rig's right-hand object, check that RightControl has Box1, Box2 and Box3 assigned. The supplied Vive bindings include GrabPinch, GrabGrip, menu and teleport.

3. Run the Windows build

Extract the Windows archive, keeping VR_DemoFbx.exe, UnityPlayer.dll, MonoBleedingEdge and VR_DemoFbx_Data together in EXE. Configure SteamVR and a tracked headset/controller pair, confirm tracking and room setup, then start VR_DemoFbx.exe. Other devices need suitable bindings and a separate compatibility check.

4. Controller mapping

- Right trigger, held: rotates all three groups around their local vertical axes at 5 degrees per second.
- Right grip, held: moves Box1 along local left and Box2/Box3 along local forward at 0.5 Unity units per second. Left grip reverses these directions. Local axes change with each group's orientation.
- Left trigger, successive presses: decreases each scale component by 0.002 on presses 1–4, increases it on presses 5–8 and resets the counter on press 9.
- Right menu, successive presses: increases local Y scale by 0.002 on presses 1–4, decreases it on presses 5–8 and resets the counter on press 9. This implements the height adjustment labelled “tilt” in the historical conceptual diagram. Neither counter-reset press changes the geometry.

These values are code parameters in Unity coordinates. The controls apply predefined linked transformations; architectural constraints and Depthmap analysis are handled separately from the interaction code.

5. Recorded checks and their scope

On 6 November 2026, a separate source copy was imported and compiled in Unity 2022.3.62f3c1. Timeline changed from 1.7.6 to 1.7.7. The files named “2026-11-06 Verified package manifest.json” and “2026-11-06 Verified package lock.json” record that check's dependencies.

ReproductionAudit.cs checked SampleScene: 133 transforms, 38 MeshFilter components, no missing MonoBehaviour scripts and one RightControl with all three targets assigned. The scene log includes their initial transforms. The source archive retains the earlier project configuration and excludes this later check script.

The archived Windows executable ran for a 15-second headless startup check before being stopped. OpenVR reported HmdNotFoundPresenceFailed. Rendering and headset/controller interaction were not tested in that check. Fan Huang's statement about successful hardware use during the original work is recorded separately in Original hardware test confirmation.txt.

The retained scene and graph files allow inspection of the saved configurations. Complete historical input and intermediate-design logs are unavailable, so they cannot reconstruct every edit or date participant sessions. Historical package and shader logs document software development.

To repeat the scene check, copy ReproductionAudit.cs into Assets/Editor in a separate project copy. Create a sibling folder named Verification logs, then run Unity in batch mode with -executeMethod ReproductionAudit.Run and -logFile. The script writes Editor scene audit.txt and exits after checking scene objects and references.

6. Record a new hardware check

Hardware verification blank.csv is an optional template for a new test. Record the date, operator, software versions, devices, action, baseline/final transforms, observed result and errors. Mark untested actions accordingly and retain any logs or screenshots with the new session. These records supplement the archived checks.

7. Reproduce the paper's analyses

Follow Supplementary data/Read me.txt for the complete command sequence and study conditions. The numerical analyses use Python 3.10+; figure generation also requires NumPy and Matplotlib.

In Depthmap, use the 0.6 m VGA Map 3 (original) and VGA Map 1 (adjusted) in Technical sources/sy.graph. Use zx2.graph for the original axial map and zx1.graph for the adjusted map. Drawing1.dxf contains the plan representations. The CSV exports preserve the attributes used in the manuscript. Record the software version and graph-construction settings if rebuilding the graphs from CAD.

Third-party notices.txt and the retained licence files describe the software dependencies.
